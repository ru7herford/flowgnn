# Recorded page observations

Generated by `python scripts/export_page.py` from cases in `data/cases/`, a
finished study in `lab/runs/train/` and the training replay in `lab/runs/watch/`
(`python flowgnn.py --config examples/watch.json`). Export requires saved weights,
normalisation scales, predictions and snapshots. Browsing requires only these exports.

`summary.json` holds, per test case, its outline, common colour bounds and the errors of
all three seeds of M0-M3; the error by links from the obstacle (`hop_bins`, `hop_error`); the
training replay (`progress`); `rounds_experiment`; `timing` (one network's prediction time
against SU2's solve time, from `python scripts/timing.py`, or null); and
`influence_distance`, the mean link distance of each input set's influence distribution over two test
shapes, three wake points and three seeds, as [lowest, mean, highest]. Pictures show one network per input set: the
seed with the median mean validation velocity error. All three seeds remain in the measured results.

All binary numbers are little-endian. For a case with N displayed nodes and T
triangles, `<case>.bin` contains, in order:

| Block | Type and length |
|---|---|
| Positions, interleaved x/y | float32, 2N |
| Triangle vertex IDs in the displayed mesh | uint32, 3T |
| Solver u, v, p, one field at a time | float32, 3N |
| Predictions M0, M1, M2, M3, each u/v/p | float32, 12N |
| Corresponding node IDs in the complete mesh | uint32, N |

Error is calculated from prediction minus reference. Each drawn pixel linearly interpolates the three corner values of its
triangle. Colour lookup quantizes the colour scale, not the recorded data; colours clip at the recorded 99th-percentile error cap.
The field meshes show a cropped window. Only the ten test cases are exported for the page; the complete
training and validation dataset remains in `data/cases/`.

The training replay retrains M0 and M3 at their shown seeds with the study's settings, recording every
2 epochs instead of every 10. GPU arithmetic is not bit-for-bit repeatable, so the replay's networks are
close to, not identical with, the study's: `progress.runs.<model>.test_velocity` sits beside
`study_test_velocity`. `progress_<model>.bin` holds the replay's horizontal velocity on the snapshot case,
snapshot × node, as uint16 over `progress.range` (value = low + q / 65535 × (high − low); one step is about
5e-5). The recorded snapshots used float16.

`graph.json` holds the complete mesh of the page's triangle, the traced centre point and its neighbours,
and that point's inputs in readable units (`example_inputs`: position, boundary type, distance and
direction to the obstacle, the six shape numbers; the network receives them scaled). `rounds` holds,
for the points within 12 links of the centre (`nodes`), the influence distribution of the centre's state
after each of the 12 rounds (`share`, one row per round; zero beyond that round's reach), and
`obstacle_links` the number of links from the centre to the obstacle.
`trace_M3.bin` stores M3's before, incoming sum, after, then edge messages for those points. The first
three blocks each use round × selected node × component order; messages use round × directed edge ×
component order. Dimensions, sources and destinations are in `graph.json`. All incoming edges are
retained. Tracing reuses the layer implementation on the full graph, and export checks the decoded
result against the saved prediction.

`reach.json` holds the complete mesh of one test airfoil for the reach page: positions, links, outline,
each point's link count to the airfoil (`obstacle_hops`), the wake point the replay starts from, and
`influence`: for each input set's shown network, the influence distribution of its predicted horizontal
velocity at that point (adapted from Xu et al. 2018, who use a hidden state: the sum of absolute Jacobian
entries of each node's inputs, divided by the total). It lists the nodes inside the receptive field, their share and the mean link distance.

`rounds_experiment` is the validation and test velocity error of the same network trained with 6, 12
and 18 message-passing rounds (seed 0, 150 epochs, from `lab/runs/rounds_6`, `rounds_12` and `rounds_18`, trained with
`examples/rounds_*.json`),
or null when those runs are absent. Solver setup and limitations are in [the dataset notes](../../data/README.md).
